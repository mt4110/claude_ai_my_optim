# Claude Code 開発運用キット

自然な会話から意図を整理し、合意した範囲で実装を進め、設計からの逸脱を見つけるための設計と導入テンプレートです。ソフトウェア開発に限定します。

普段の入口は「ここを直して」「まず相談したい」という会話です。kit・スキル・ハーネスを毎回選ぶ必要はありません。最初に[利用境界と日常の使い方](docs/USAGE-BOUNDARIES.md)を読めば、必要な構成を選べます。

この利用者向けには[個人用の設定](personalization/owner/README.md)も用意しています。自然な対話、重要な承認、製品と研究の優先順位、批判的な検討の好みを反映しています。汎用キットへ一律に適用せず、必要なプロジェクトに統合する構成です。

「Claudeは型が前提だから」というモデルの性格だけでは原因を説明しません。意図の取り違え、文脈の欠落、広すぎる権限、検証不足を分けて扱います。ChatGPTとの快適さの同等性や、不具合・逸脱の完全防止は未検証です。

2026年10月7日の公式資料に基づく設計版です。日本語の設計書、場面別ガイド、導入用の指示・スキル・設定例、無人実行ハーネスの仕様と試験ケースを含みます。

個人用の基本指示を配置する導入スクリプトは実装済みです。合成プロジェクトで19件の確認を行っています。Claude Codeでの指示の実動作と、無人ハーネスは別途未検証・未実装です。

**実行制御ハーネスは未実装です。設定例だけで安全な無人実行ができるとは扱いません。** Claude Codeへの導入、実機検証、GitHubへのpush・公開、委託先のコード・ログへのアクセスは行っていません。

## 読む順番

一回の実行で個人用設定を入れる場合は、対象プロジェクトの直下で配布元の`install.sh`を実行します。変更予定だけを見る`--dry-run`もあります。[使い方と既存ファイルの扱い](docs/INSTALLER.md)。

```sh
bash /path/to/claude_ai_my_optim/install.sh
```

1. [利用境界と日常の使い方](docs/USAGE-BOUNDARIES.md)：普段使うものと、必要になってから足すもの。
2. [導入手順](docs/SETUP.md)：最小構成だけを既存プロジェクトに統合する。
3. [場面別の使い方](docs/SCENARIOS.md)：必要な場面だけ参照する。

設計を詳しく確認する場合は[設計全体](docs/DESIGN.md)、Copilotの履歴を渡す場合は[引き継ぎ手順](docs/COPILOT-MIGRATION.md)、モデルを選ぶ場合は[モデルと推論設定](docs/MODELS.md)を参照してください。日常利用の前に全ドキュメントを読む必要はありません。

設計の詳細は[ハーネス仕様](docs/HARNESS.md)、[権限・脅威・限界](docs/SECURITY.md)、[文脈とトークン](docs/CONTEXT.md)、[検証と終了条件](docs/EVALUATION.md)、[実装順序](docs/ROADMAP.md)にあります。一次資料と採否は[出典台帳](docs/SOURCES.md)で確認できます。

今回の実施済み・未実施は[確認記録](docs/VALIDATION.md)にまとめています。

## 基本構成

```text
このリポジトリ
├── install.sh             個人用の基本指示を導入。権限・スキルは自動変更しない
├── docs/                  設計・導入・場面別ガイド・出典
├── kit/                   対象プロジェクトへ持ち出す最小構成
│   ├── CLAUDE.md          短い常設指示
│   ├── .claude/
│   │   ├── rules/         変更対象に応じた補助指示
│   │   └── skills/        認識合わせ・実装・レビュー・引き継ぎ
│   └── docs/work/         プロジェクト情報。判断・現在の作業は必要時に追加
├── profiles/              手動レビュー用の設定例。自動適用しない
├── personalization/       明示された利用者の方針。汎用部分とは別に導入
├── templates/             作業合意・検証・例外・ログ引き継ぎ
├── harness/               制御の仕様に対応するデータ例・試験ケース
├── tests/                 合成プロジェクトでの導入試験
├── CONTRIBUTING.md        貢献方法
├── CONTRIBUTORS.md        貢献者の記載方針
└── LICENSE                MITライセンス
```

`kit/`を丸ごと無条件で上書きする運用はしません。必要なファイルを既存の指示・設定と照合して統合します。対象の言語・OS・ビルド・テストコマンドは導入時に設定します。

## 最初の依頼例

```text
ログイン後に一覧が消える。今の認証方式は変えずに直して。
```

ユーザーが毎回フォームを埋める必要はありません。Claudeが会話と既存資料から必要項目を整理し、結果を左右する不明点だけを確認します。小さな修正では大きな設計書を作りません。

最初の持ち出しは`kit/CLAUDE.md`と、必要なプロジェクト固有条件だけです。スキルは任意の補助、ハーネスは無人実行を制御する別の仕組みです。kitを導入しただけでハーネスが動くことはありません。

## 採用するもの・採用しないもの

| 項目 | 判断 |
| --- | --- |
| 短いCLAUDE.md | 常設の行動原則と参照先を置く |
| スキルと場面別ガイド | 必要なときに読む。権限を勝手に増やさない |
| 合意と検証の対応表 | 設計書を「守ったつもり」で終わらせない |
| フック・権限・隔離環境 | 役割と限界を分けて設計する |
| XML | 複数資料の区切りに必要な場合だけ使う |
| 無制限のRunAlways | 初期構成に採用しない。製品固有の設定名と実際の権限を先に確認する |
| 自動的なサブエージェント増員 | 採用しない。必要性・分担・予算を合意してから使う |
