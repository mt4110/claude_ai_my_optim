# 合意した実装

対象：$ARGUMENTS

1. 作業合意、最新の訂正、承認範囲を確認する。合意ファイルの状態欄だけを実行許可にしない。
2. ブランチ、既存変更、関連するコードと仕様を確認し、現状と計画の矛盾を示す。
3. 範囲内で最小の有効な変更を行う。依存追加・全体改修・仕様変更を善意で広げない。
4. 新しい重要判断や権限が必要なら、その部分を止め、理由、影響、選択肢を提示する。独立した許可済み作業は進める。
5. 変更に合う検証を実行する。コマンドの副作用と実行環境を確認し、テストの条件を弱めない。
6. 受け入れ条件ごとに、変更箇所、証拠、未検証を照合する。検証後の変更は再確認する。
7. 結果、理由、検証、残る制約、必要な人の判断を報告する。

停止条件：範囲外、設計との重大な矛盾、検証不能、同じ失敗の反復、予算・時間超過。削除・公開・本番操作・分担・モデル変更には既存の承認方針を適用する。
