# 変更のレビュー

対象：$ARGUMENTS

1. 目的、合意の版、対象のベースと差分を確認する。既存変更と今回の変更を区別する。
2. 条件ごとに、実装箇所と証拠があるか確認する。範囲外変更、仕様の取り違え、失敗時の状態を優先する。
3. 認証・認可、入力、データ、並行処理、キャンセル、資源解放は変更に関係するものだけ確認する。
4. テスト・CI・期待値を弱めた変更や、実環境の未確認を成功とした報告がないか確認する。
5. 問題は該当ファイル・箇所、発生条件、影響、根拠とともに示す。問題が見つからないことを安全の証明にしない。
6. 合格、未確認、不成立を条件別に報告する。レビュー依頼だけではコードを修正しない。

必要な検証の実行、修正、サブエージェントによる別レビューは、それぞれの承認範囲を確認する。
