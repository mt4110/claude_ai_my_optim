# 認識合わせ

依頼：$ARGUMENTS

1. 適用指示、現在のプロジェクト情報、今回に関係する仕様・判断を確認する。全資料を一括で読まない。
2. 重要な原文を保ち、目的、現状、変更範囲、不変条件、確認方法を短く整理する。
3. 事実、仮定、提案、未決事項を分ける。結果を左右する不明点だけ確認する。
4. 小さく明確な修正では短い返答を合意案とし、不要な設計書を作らない。大きな変更では作業IDを付けて合意案を提示する。
5. 記録の作成が許可されている場合だけ、プロジェクトで決めた場所に草案を保存する。元の設計・承認済み条件を上書きしない。
6. 必要な実装承認がなければ実装へ移らない。すでにある承認を繰り返し尋ねない。

この呼び出しは調査・合意整理の依頼であり、ソース編集、公開、外部送信の追加許可ではない。スキルの起動は強制的な権限制御ではない。
