# 設定例の扱い

ここには自動適用しないJSON例を置く。構文が正しいことと、対象版で意図した実効権限になることは別である。

- `supervised.settings.example.json`：監督付き作業の出発点。汎用シェル、外部ツール、分担を人の確認へ戻す。
- `observe.settings.example.json`：参照中心の調査用。代表的な編集・シェル・外部連携経路を拒否する。全ての新規ツールを包括的に制限する保証はない。

どちらもモデルを指定せず、フックの未実装ファイルを登録しない。`.env`の拒否は機密パスの例であり、全認証情報を保護する設定ではない。Bash等の読み取りは別に管理する。

既存の設定源や管理設定を確認し、必要項目を人が統合する。`ask`は既存の許可と組み合わせた実効状態を確認する。プロジェクト内のJSONを、エージェントから変更できない管理設定と同じ強度で扱わない。

監督付き例には`failIfUnavailable: true`を入れている。サンドボックスが起動できない場合は無隔離で継続せず、起動に失敗させる意図である。対象版・OSで確認し、使えない場合にこの項目を黙って外さない。公式資料ではネイティブWindowsのサンドボックスは非対応であり、WindowsではWSL等の対応環境を別途検討する。

サンドボックス外への再試行を防ぐ`allowUnsandboxedCommands: false`は、人が管理する`--settings`または管理設定から与える方法を優先する。ユーザー設定から与える場合の優先関係にはバージョン依存がある。プロジェクト内の設定例だけで、他の設定源や除外コマンドを含む実効制限を固定したとは扱わない。ドメインの空配列も、既存の許可を全て消す設定ではない。

導入時は[設定](https://code.claude.com/docs/en/settings)、[権限](https://code.claude.com/docs/en/permissions)、[サンドボックス](https://code.claude.com/docs/en/sandboxing)を対象版で確認し、画面・実動作で検証する。詳細は[導入手順](../docs/SETUP.md)。
