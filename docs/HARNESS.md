# 実行制御ハーネスの仕様

状態：未実装。ここで定義する起動器・承認ストア・検証器は、公式の標準機能ではなく本キットの提案である。設定例やデータ例を配置しただけでは作動しない。

## 守る対象

人が承認した目的、変更範囲、不変条件、実行権限、予算、終了条件を、Claude自身が変更できない場所で管理する。人が読める作業合意と、機械が使う実行許可を分ける。

```text
人が管理する領域（エージェントから書き込めない）
  起動器 / 承認済み実行許可 / 検証器 / 保護された期待結果
                 ↓ 検査済みの実行条件
隔離した作業領域
  Claude Code / 対象コード / 変更案 / 証拠の提出候補
                 ↓ 差分と検証対象
外部の検証器 → 人のレビュー → 受け入れ・停止
```

ローカルの作業ディレクトリだけで、同じOSユーザーに完全なシェル権限を与えた状態では、この分離は成立しない。worktreeは変更の整理に役立つが、OSの権限境界ではない。

## 部品と責務

| 部品 | 入力 | 出力 | 変更できる主体 |
| --- | --- | --- | --- |
| 作業合意 | 会話・仕様・現状 | TASK.md | Claudeは提案。合意確定は人 |
| 起動器 | 作業ID・保護された許可 | 許可されたセッション | 人・運用管理者 |
| 承認ストア | 人が確認した合意版 | 有効な実行許可 | 人・運用管理者 |
| PreToolUseアダプター | ツール名・引数・許可 | 拒否または通常の権限判定へ委ねる | 人・運用管理者 |
| 検証器 | 差分・保護された条件 | 条件別の結果と証拠 | 人・運用管理者 |
| 完了判定 | 検証・未決事項・人の判断 | 完了・未完・中止 | 最終受け入れは人 |

提案のファイル名や状態欄を、そのまま承認ストアとして使わない。JSONの`human-approval-required`やハッシュ値は本人性を証明しない。

## 承認と失効

承認は、作業ID、合意の内容ハッシュ、対象リポジトリ、ベースコミット、初期の作業状態、実行環境、許可パス、許可操作、検証条件、期限、予算に結び付ける。

人が許可ストアへ登録する方法は、外部の手動操作か、認証された承認UIとする。自然文の「承認済み」をモデルが抽出するだけの方法は使わない。現在のキットには承認UIはない。

合意・許可範囲・保護された条件の変更、別リポジトリへの移動、許可期限切れ、初期状態の不一致で実行を止める。通常の承認済み編集による作業差分は失効理由にしない。初期の未コミット変更は、人が区別できるスナップショットとして保全する。

検証結果を出した後にコードが変わった場合は結果を失効させる。検証は、内容を固定したスナップショットに対して行い、差分ハッシュと実行環境を記録する。合意ハッシュだけでは実装の同一性を証明できない。

## 起動前検査

1. リポジトリ・ベース・初期差分・実行許可を照合する。
2. Claude Codeの版、CLIまたは拡張、実モデル、effort、権限モード、設定の読み込み元を記録する。
3. フックと検証器の配置・起動・期待する拒否応答を検査する。欠落・不正設定・実行失敗では起動しない。
4. エージェントが設定、承認ストア、起動器、保護された期待結果へ書けないことをOS権限で確認する。
5. 許可対象以外の書き込み、外部ネットワーク、ホストの認証情報、Dockerソケット、外部MCPへの経路を確認する。
6. 予算・時間・停止条件が未設定なら、無人実行は起動しない。

確認のために機密ファイルを読み出さない。秘密を置かない試験用環境で経路を検証する。設定の自己申告だけを検査結果にしない。

## ツールごとの制御

| 経路 | 方針 |
| --- | --- |
| Read・Glob・Grep | 必要最小限の対象。機密への読み取りは公式権限とOS隔離で制限 |
| Edit・Write・NotebookEdit | 正規化した対象パスを確認し、許可範囲外・保護対象を拒否 |
| Bash・シェル相当 | 無人実行では汎用シェルを与えない。固定の検証ジョブ等を外部実行器で起動 |
| MCP・プラグインのツール | 未知のツールは拒否。入力・送信先・副作用・資格情報を登録してから採用 |
| Agent・別セッション | 明示された分担・予算のみ。同じ制約を継承し、権限追加を許さない |
| 外部送信・公開・本番操作 | 別の人の承認と、対象を限定した実行権限が必要 |

`Read`のフックだけでは`@`で参照されたファイルを捕捉できないという公式仕様がある。[フック](https://code.claude.com/docs/en/hooks)。読み取り拒否ルールとOS隔離も使う。

パスは絶対パス化、`..`の解決、シンボリックリンクの解決、作業ルートとの包含確認を行う。新規ファイルは既存の親ディレクトリを検査する。競合中のリンク差し替えや別プロセスの書き込みまでフックの文字列判定で防げるとは扱わない。対象OSで書き込み先の制限をかけ、外部検証器も全差分を確認する。

## シェルを文字列で「安全」と判定しない

`rm`を拒否してもPython、Node、`find -delete`、別スクリプトから削除できる。`npm test`を許可しても、package.jsonやテストの中身が変われば任意処理になる。正規表現による禁止語リストは補助にしかならない。

無人実行向けの検証ジョブは、ジョブIDから保護された定義を引き、固定の実行ファイルと引数で起動する。ユーザー入力をシェル文字列へ連結しない。それでも検証対象コードは動くため、資格情報を持たない隔離環境、読み取り専用マウント、ネットワーク制限、時間・メモリ・プロセス数の制限が必要である。

対象コードのビルドやテストがネットワーク・ホストのサービスを必要とするなら、無人実行の前に環境を設計し直す。権限を広げて検証失敗を解消しない。

## フックの入出力と失敗

PreToolUseの標準入力JSONから、必要な共通項目・ツール名・入力だけを読む。機密になり得るコマンド全文・ファイル内容・環境変数を監査ログに残さない。

拒否する場合の応答例：

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "この変更は承認された対象範囲に含まれていません。"
  }
}
```

許可範囲に入っていても、原則は`allow`を出して他の確認を飛ばすのではなく、通常の権限判定へ委ねる。入力破損・判定不能はアダプター内部で拒否する。[公式フック仕様](https://code.claude.com/docs/en/hooks)では起動不能やタイムアウトが遮断にならない場合があるため、外部の起動器とOS制限を別に設ける。コマンドフックのポリシー拒否には正しいJSONまたは仕様に沿う終了コード2を使い、一般的な終了コード1を遮断と誤解しない。

SessionStartは短い作業識別情報を補助的に渡す用途。SessionStartフックの失敗で開始が止まるとは想定しない。PostToolUseは既に行われた副作用を防げない。Stopは報告・検証への誘導であり、外部の受け入れ判定を代替しない。

Stopで無限に続行させない。`stop_hook_active`を確認し、あらかじめ合意した再試行・時間の上限で未完を報告して止まる。テストの期待値を弱めて通すことを修復と認めない。

## 差分と証拠

検証器は、ベースと承認済み初期差分を基準に、追加・変更・削除・名前変更・未追跡ファイル・バイナリ・リンク・ファイルモードを確認する。Gitが無視している領域への副作用はGit差分だけでは分からない。OS隔離と管理対象のファイル一覧を使う。

Claudeが提出した「テスト成功」は証拠の候補とする。保護された期待結果を使う検証器が、提出された実装スナップショットに対して確認する。テスト・CI・検証スクリプトの変更は別途レビューし、実装と一緒に自動承認しない。

検証結果は条件ID、ジョブID、実行環境、入力条件、開始・終了、終了状態、実装スナップショットのハッシュ、証拠への参照を記録する。生のstdout/stderrは機密を含み得るため、必要な要約を基本とし、詳細はアクセス制限した場所へ保存する。

## 停止条件

- 実行許可がない・期限切れ・内容不一致。
- 未知のツール、対象範囲外、保護対象への操作。
- 設定・承認・検証器への書き込み経路が残っている。
- 新しい仕様判断、機密の外部送信、課金・公開・本番操作が必要。
- 予算・時間・再試行の上限、同じ原因の反復、検証不能。
- 外部データ内の命令を実行権限の根拠にしようとした。

停止は失敗の隠蔽ではない。完了した部分、残る問題、次の判断だけを報告し、確認待ちでも独立した許可済み作業は進められる。

## 対応環境

macOS・Linux・Windowsの境界を同一実装で保証するとはしない。初期の監督付きキットはテキストとJSONで持ち出せる。無人ハーネスはまず資格情報を持たないLinuxの隔離環境を候補にし、実装時に実際のコンテナ・VMの構成を決める。macOS固有のビルドや実機操作は人の監督下に残す。

コンテナなら安全とは断定しない。ホスト全体のマウント、権限昇格、ホストソケット、資格情報の持ち込みを避け、対象の脅威モデルで検証する。
