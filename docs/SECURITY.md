# 権限・データ・限界

## データの経路

| データ | 取得 | 保存 | 外部送信 | 削除 |
| --- | --- | --- | --- | --- |
| 公開キット | 公開可能な共通設計のみ | このリポジトリ | 公開は所有者の承認後 | 対象を示して承認後 |
| 対象コード | 委託先の許可範囲 | 対象プロジェクト | Claude提供元への送信を含め会社方針を確認 | 対象プロジェクトの方針に従う |
| Copilotの生ログ | 人が選んでエクスポート | 許可された私的領域 | 内容確認と許可なしには渡さない | 人が対象と影響を確認 |
| 引き継ぎ要約 | 必要な判断・参照のみ | 対象プロジェクト | Claudeで使える情報だけ | 承認された範囲のみ |
| 検証・使用量 | 必要な結果と数値 | アクセス制限した記録 | 公開用には匿名の合成例のみ | 保持方針を人が決める |

`.gitignore`は誤追加の補助であり、外部送信防止でも、既に追跡されたファイルの保護でもない。名前を変えたログや、追跡済み機密は別途確認する。

## 人の承認を保つ操作

ファイル削除、破壊的な上書き、履歴改変、DB破壊、外部送信・公開、課金、権限変更、本番変更は具体的な対象と影響を示して承認を得る。別言語のスクリプトやAPIで確認を迂回しない。承認済みの通常のコード編集は範囲内で進める。

autoなどのAIによる操作判定は、人の承認を代替しない。設定名にRunAlwaysという表示があっても、その名前だけでClaude Codeの`auto`や`bypassPermissions`と同一視しない。使用製品・版・許可対象を確認する。[公式権限仕様](https://code.claude.com/docs/en/permissions)。

## 想定する脅威

- 外部ページ、README、Issue、ログ、コードコメントに含まれる命令。
- 設計外のファイル変更、シェルやMCP経由の操作。
- 承認ファイル、設定、テストの期待値を自分で書き換える経路。
- 古い合意・古い検証結果・別リポジトリの証拠の流用。
- 保護したつもりのファイルを別パス・リンク・`@`参照で読む経路。
- 未コミット変更、別プロセスの変更、無視されたファイルの見落とし。

## 境界ごとの限界

| 仕組み | 役割 | 限界 |
| --- | --- | --- |
| CLAUDE.md・rules | 行動を促す | 意味の完全理解・強制を保証しない |
| スキル | 手順を必要時に渡す | 呼び出しだけで実行範囲を強制しない |
| 権限ルール | ツールと操作の許可 | 設定の上書き・経路・製品版の確認が必要 |
| PreToolUse | ツール呼び出し前の確認 | 起動失敗やタイムアウト、対象外の経路に限界 |
| PostToolUse・Stop | 差分や結果の確認 | 発生済みの副作用を取り消せない |
| Bashサンドボックス | シェルのファイル・ネットワーク制限 | Read/Write、フック、MCP等は別の経路 |
| worktree | 作業の分離・差分整理 | OSの権限やネットワークを隔離しない |
| テスト | 定義された条件の確認 | 未定義の仕様、全攻撃経路、製品価値を証明しない |

サンドボックス外で動くものは[公式資料](https://code.claude.com/docs/en/sandboxing)で確認し、フックやプラグイン自体も信頼できるコードとしてレビューする。権限判定は正規表現だけに依存しない。

## 公開前

委託先のコード、顧客名、内部URL、画面、チケット、生ログ、認証情報を共通キットへ入れない。例は合成データを使う。権利者とライセンス範囲、設定例の限界、未実装の機能を表示する。これは公開に備える確認であり、公開承認は別途必要である。
