# 検証と終了条件

状態：検証計画。現場のClaude Codeを使った性能・品質比較は未実施。

## 検証する仮説

「短い合意と明確な権限・検証が、長い指示ファイルだけの運用より、認識の修正と範囲外変更を減らすか」を確認する。モデルそのものの優劣や、ChatGPTとの全面比較を研究目的にしない。

接続先は現在の業務の修正・レビュー負担である。このキットの開発を主力プロダクトより優先する長期研究にしない。

## 比較条件

同じモデル・effort、同じベースと入力、同じ環境、同じ検証条件で比較する。変更内容を知った再実行は学習効果が混ざるため記録する。現行運用が危険なら再現のために危険な権限を与えず、非機密の隔離した課題に置き換える。

最初の対象は、既知のバグ修正、限定した機能追加、設計から逸脱しやすい変更とする。件数は稼働時間と現場の代表性に応じて人が決める。小さな標本から一般的な改善率を主張しない。

## 記録するもの

| 項目 | 記録方法 | 解釈の注意 |
| --- | --- | --- |
| 認識の修正 | 目的・仕様の訂正内容と所要時間 | 正当な不明点の確認と、取り違えを分ける |
| 範囲外変更 | 合意と差分の照合 | 計画が曖昧ならその欠陥も記録 |
| 検証の成立 | 受け入れ条件ごとの証拠 | ビルド・モック・実環境を分ける |
| 完了誤報 | 未検証・失敗を完了と報告したか | 未完を正しく報告することを罰しない |
| 人の負担 | 確認・差し戻し・レビュー時間 | AIの待ち時間だけで評価しない |
| 使用量 | 入力・キャッシュ入力・出力、分担込み | 取得範囲と元の定義を明記 |
| 製品への効果 | 実際の作業が完了したか | 設計の見栄えやテスト数を代用しない |

## 技術的な受け入れ

監督付き構成は、読み込まれた指示・設定を確認し、実装前の認識、範囲外操作、報告の区別を代表作業で確認する。

無人実行は[ハーネス試験](../harness/CASES.md)の安全境界に関わる項目を省略しない。ハーネスが未実装、起動器や隔離が未確認、重大な抜け道が残る場合は無人実行を解放しない。

## 継続・縮小・中止

- 継続：認識修正・レビューの負担に実用上の改善があり、重要な境界を守れた。
- 縮小：簡単な作業でテンプレートが過剰なら常設指示と手順を減らす。
- 中止：同じ逸脱が制御できない、重大な経路が残る、確認負担が改善しない、現場の作業を圧迫する。

終了時点と使える時間を開始前に人が決める。未設定なら比較実験・無人実行は始めない。終了条件を後から緩めて成功扱いにしない。
