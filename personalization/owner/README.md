# 個人用の設定

この会話で明示された利用者の方針を、[PERSONAL.md](PERSONAL.md)へ整理した。過去案件の一覧、委託先の情報、端末のパス、アカウント情報、生ログは含めない。

## 使うとき

個人用の最小構成は、対象プロジェクトの直下で配布元の`install.sh`を実行すれば導入できる。[導入スクリプトの使い方](../../docs/INSTALLER.md)を参照。PERSONAL.mdは`.claude/local/`へコピーし、CLAUDE.local.mdから参照する。以下は手動で統合する場合の方法。

対象プロジェクトの既存指示と重複・矛盾を確認し、必要な方針だけ統合する。全文を使う場合は、PERSONAL.mdを対象プロジェクトの任意の場所へ配置し、既存のCLAUDE.mdから参照する。たとえばプロジェクト直下へ置いた場合は、次の行を加える。

```text
@PERSONAL.md
```

これは会話での判断と応答を調整する文書であり、ハーネスや権限設定ではない。読み込まれたことと、実際に意図どおりに動くことを分けて確認する。今回、対象案件への配置・有効化は行っていない。

個人設定は指示の一部として変更管理する。監督付きの設定例とハーネスの許可例には、プロジェクト直下のPERSONAL.mdを保護対象として含めている。別の場所へ配置するなら実際のパスに合わせる。通常の開発作業で個人設定を黙って変更させず、更新を依頼するときだけ人が対象と差分を確認する。シェル等の別経路も含む強制は、設定例だけでは保証しない。

毎回この設定を選ぶ操作は不要。導入後は普通に依頼する。すでにAGENTS.md等に同じ方針があるなら、全文を重複して読み込まず、足りない部分だけ統合する。

## 適用の境界

- 利用者の製品方針は、自分の製品の優先順位・設計・研究の相談に使う。
- 委託先の仕事では契約・仕様・担当範囲を確認し、個人の事業方針で勝手に変えない。
- 現在の指示・訂正を古い個人設定より優先する。個人設定を根拠に操作権限を追加しない。
- モデル選択の事前確認は、利用者が明示した要件として保持した。便利さを理由に黙って外さない。同じ作業の継続では繰り返さない。

## 今後の調整

[会話例の確認項目](CHECKS.md)で、望む動きと避けたい動きを確認する。実際に起きた取り違えがあれば、一般論を増やす前に、その発言・解釈・行動のどこが違ったかを直す。会話の癖や性格を推測して追記しない。
